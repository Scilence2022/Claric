# Claric 从 Harness 到产品交付的深度审查

日期：2026-09-05。审查基线：`c9a38a4` 及本次工作树。参考：`harness-analysis-report.md`，但结论以源码行为和实际验证为准。本文是问题分析与目标设计，不是发布批准；本轮修改的验证结果另见末节。源码引用用于定位原始问题，修改后行号可能变化。

## 1. 总结：真正需要改变的是执行契约，而不是前端框架

Claric 已有较好的纯逻辑层、Word 适配层、提案预览、依赖注入和大量回归测试。不能因文件大、没有 React 或旧 E2E 休眠就判断架构不可用。相反，不应低估其正文差分、书签重定位、表格及图像操作的领域复杂度，全面重写会丢失这些回归资产。

但它仍不能仅凭 Jest 全绿被称为产品级交付。关键缺口是：

1. **执行权限分散。** 生成、自动应用、重试、取消、新会话和 MCP 调用没有共享的运行所有权与副作用策略。
2. **文档目标与操作结果不够统一。** 不同操作使用当前选区、文本比较、书签或图像元数据；某些失败发生在部分写入之后，普通“重试”不能保证安全。
3. **验证覆盖的是实现片段，不是完整交付承诺。** 构建前检查旧 dist、Pages 验证旁路、真实 Word 缺位，使测试数与发布信心脱节。
4. **界面将内部状态留给用户推断。** 颜色点、隐藏日志、自动保存和显式 Save 并存、取消立即恢复可操作状态，容易掩盖未完成或不可撤销操作。
5. **开发 harness 与产品内 agent runtime 混称。** HTTP 日志总线只是开发测试基础设施；真正影响用户的是 conversation/tool-loop/Word 写入的执行约束。

推荐渐进式但实质性的架构调整：保留算法与 DOM 组件，建立运行所有权、统一提案与目标锚点、串行文档写入执行器、外部工具授权、分层验收五个明确边界。不是先换框架，也不是只加几个确认框。

## 2. 对参考报告的批判性校正

原报告对端点拓扑、默认关闭、server half 缺少客户端、路径穿越已修等事实的调查有价值。以下结论应收紧：

| 原表述或推断 | 源码事实 | 应有结论 |
|---|---|---|
| 日志为内存环形 | `scripts/dev-e2e-middlewares.cjs:95` 无限 push，`:133` 只截断响应 | 有响应窗口，没有存储上限 |
| fix/trace 崩溃丢失窗口为 0 | `:253-278` 吞持久化失败后返回成功；覆盖写不是原子持久化 | 即时写入不等于成功确认，更不等于断电零丢失 |
| process.once 防止重复 setup 叠加 | `:293-302` 每次 setup 创建并注册新函数 | once 只限制单个监听器执行次数，不保证生命周期幂等 |
| pause 不可达时 OR 状态仍保证等待 | `:335` 只计算当前内存布尔值，未收到 pause 不会改变状态 | 需要 run identity、领取与租约；不是布尔表达式能解决的网络问题 |
| 每轮必须 trigger | `:345-372` 无领取消费和迭代标识 | 放行是持续状态，不是单轮一次性许可 |

| verify 与 CI 同构且健康 | `package.json` 不包含 audit/镜像扫描；独立 Pages workflow 原缺 coverage/typecheck/audit | 需分别列源码、产物、供应链、部署和宿主门禁 |
| 内容 hash 可跨机器复现 | 原路径分隔符未标准化，且依赖实际构建字节 | 只能承诺相同资产集产生相同摘要，不承诺不同环境必然产出同字节 |

不沿用旧报告的测试数量，也不把“当前工作树失败只是正常 TDD”当作可以交付的证明。参考报告保持历史快照，本报告和当前源码记录后续变化。

## 3. 风险与改进优先级

P0 指影响发布证据或可能让授权失效的发布阻断项；P1 指主流程正确性与恢复能力；P2 指长期治理或低频体验。严重度不是漏洞评级，静态风险不会被写成已在用户文档中发生的数据损坏。

### 3.1 运行生命周期、取消和重试

**确认问题。** `conversation.js:2142-2156` 在忙碌检查之后等待选区，允许两次提交同时通过前置检查。新会话在 `:2252` 取消后清空，而旧结果仍可能到 `:2213` finalize。`chat-view.js:944` 向当前会话数组写入，未绑定生成时的会话身份。

`conversation.js:2235` 发起取消就释放部分忙碌状态，但 Word 已排队的批次不能靠 AbortController 撤回。格式和图像 Apply 回调原未完整传递 signal。现有卡片间互斥值得保留，但它不能替代所有 Word 写入口共享的写锁。

**重试不是重复点击。** `word-actions.js:3357` 原 `retryFailed` 重新生成后直接应用，且未传应用取消信号；失败清理又可能删除再次重试需要的书签。用户对旧提案的授权不能自动覆盖新的模型输出。

**设计。** 采用 `idle → preparing → generating → awaiting-review → applying → cancelling → settled` 状态；第一次 await 前取得 `runId/sessionId` 所有权，提交结果与释放状态必须验证所有者。取消停止后续工作，但写锁等当前宿主批次真正结束后才释放。重试产生新的 proposal revision，保留原始参数与未决项目，必须重新确认。

**验收。** deferred selection/LLM/Word sync 分别控制双提交、取消后新聊天、迟到成功、第二项写入时中止。断言既不混入新会话，也不把部分写入描述为完全撤销。

### 3.2 文档锚点与副作用执行

**确认问题。** `word-actions.js:2569/2602` 格式提案原未保存稳定目标，Apply 使用当时选区。文本路径的原文比较能拦截文本改变，但无法单独识别相同文字的另一段。图像路径已有身份校验（`agent-actions.js:1155`），并非完全无保护；不过元数据指纹不等于图像内容身份（`image-model.js:144`）。

多步格式/图像修改逐项 sync，后项失败不回滚前项。部分路径强制关闭跟踪而非恢复原模式，或先替换图像再保存来源，后续失败无法用“未应用”概括。

**统一提案契约。** `proposalId/revision/documentRef/targetAnchor/baseline/operations/preconditions/approval/result`。其中 documentRef 必须通过实际宿主能力获得或在当前打开文档生命周期内绑定，不凭文件名猜测；range/bookmark 存在后仍须复核基线。历史保存审阅与结果记录，不把已失效闭包恢复成可执行提案。

**执行器契约。** 每文档串行、每项有结果 `pending/applied/no-change/failed/unknown`。未知代表 API 超时后无法确认是否写入，应重读并请求用户检查，不能盲目重放。跟踪模式在作用域内读取、设置并在 finally 恢复。Word 非事务 API 不应包装成虚假的全有或全无事务。

### 3.3 MCP 与模型运行 Harness

现有 `tool-loop.js` 的步数、重复调用、观察和请求字节预算是优点；应保留，并区分成本预算、时间预算和权限边界。

**确认问题。** `mcp-client.js:117` 原收到响应头就清理超时，正文仍可长时间不结束；`tool-loop.js:339` await send 后未再次检查取消，execute 的 AbortError 在 `:401` 被转成普通观察。MCP 工具调用通过 `mcp-tools.js:163` 直接派发；工具结果不直接写 Word，并不代表远端工具没有副作用。

**目标策略。** transport 从建连到读完整正文均有 deadline、大小限制与 signal；SSE 按请求 ID 增量匹配，不以连接关闭作为唯一完成条件。对外部工具建立允许清单，区分读取、外发数据、远端写入、破坏性操作；未知工具风险默认需要确认。MCP annotations 只能辅助提示，不能被不可信服务用来自动授予权限。日志显示服务与工具及脱敏参数摘要，不能为了排错默认存完整文档和凭据。

**模型质量。** deterministic stub 验证权限与调用顺序，固定脱敏文档验证目标和保真约束；真实模型评估另行记录模型版本、延迟、成本与失败类型。不得把措辞精确一致作为所有生成任务的通过条件，也不得只验证 JSON 可解析。

### 3.4 界面从开发工具变成可恢复工作流

现有聊天、选区预览、提案分项 diff、图片/表格预览应保留。拒绝尚未应用的提案不写文档，不应无差别加二次确认；真正需要明确授权的是开启自动写入、删除配置、外部工具副作用。

**首次使用。** 默认 Ollama 是一种开发默认，不是多数用户已配置的证据。欢迎状态应区分未配置/连接中/失败/可用；配置模型是明确动作，不能强迫用户从红点进入隐藏日志推断原因。云端、局域网和本地部署需要各自的连接诊断，图像配置独立于聊天配置。

**错误恢复。** 附件类型/大小/解析错误保留在附件区域；连接错误提供配置与重试，不能只使用 tooltip。401、无模型、CORS、超时等可解释类别优先于原样展示上游响应。多个文件一批导入时，后一个成功不能抹掉前一个失败；新会话不能收到上一个会话迟到的附件解析结果。

**自动应用。** 默认关闭；开启须明确这是持续写入授权，并说明宿主结构修订限制。每张卡真正执行之前重新检查授权与跟踪设置，生成失败或用户关闭后不再消费待执行队列；关闭不能撤销已经提交的 Word 批次。已应用或已拒绝的卡必须在公共 API 层幂等，而非只依赖按钮 disabled。

**可访问性与窄面板。** IME 组字期间不可拦截 Enter/方向键；发送变取消时 accessible name 同步变化。对话框有焦点进入、限制、Escape 和返回；combobox 的视觉选择、键盘选择、ARIA 状态一致。320/400/600px 及 200% 缩放检查表单、工具栏、MCP 配置行与错误长文本。优先可读密度、稳定尺寸、明确焦点，不引入营销首页或装饰卡片。

**设置治理。** 将配置草稿、验证、保存、连接测试分离。先选择统一“保存生效”或一致的自动保存，避免不同控件混合语义。删除自定义 prompt/MCP 配置需可取消或可恢复；清日志只是本机诊断删除，不代表服务商数据删除。不要为了统一弹窗构建大型 UI 框架。

### 3.5 本地持久化与隐私

`sessions.js:333-345` 原配额恢复删除其他正文后仍写旧索引；损坏索引下 clearAllSessions 不能清除孤儿正文。配额导致的裁剪应有可见状态，历史不是可靠的文档修改审计账本。后续可按需引入 IndexedDB，但不是修正索引一致性的前提。

`app-state.js:367` 整体配置含凭据存 localStorage；这不等于加密凭据保险库。产品应提供会话凭据模式、可关闭历史、导出/清理与保留策略。浏览器端自加密但密钥也存在同源环境，不能解决同源脚本被攻破的问题。

隐私应覆盖聊天、图像、附件、MCP、代理和启动连接测试。仅配置本地聊天模型不能保证云端图像/MCP 路由也本地。应明确数据送达端点及 relay 后适用对方保留策略，删除本机历史不能撤回已发送数据。HTML/SVG 净化只能限制活动内容，不能当作语义提示注入防线。

### 3.6 开发 E2E Harness

**保留，但重定义责任。** 默认关闭的开发 HTTP 总线不值得直接升级成复杂测试平台；先形成受控协议，再接真实驱动。最低要求为：版本、认证、Origin 白名单、有界 body/日志、run identity、一次性 claim、超时与幂等、持久化失败非成功响应、资源清理与非空 fixture。

推荐状态 `paused → ready → claimed → paused`，claim 限定 run/iteration 身份；过期租约恢复为显式超时，不能静默执行下一轮。trigger/claim/pause 是开发调度，不是用户文档自动写权限。

日志使用服务端单调游标与保留窗口；客户端落后需显式 gap 提示。正文和 trace 默认最小化，仅合成/脱敏用例可保留全文。原子 rename 改善半写文件风险，不承诺断电零丢失。中间件不应抢 process.exit 或清除其他监听器。

协议测试使用真实本地 HTTP 和 fixture；真实 Word 驱动必须标记构建、宿主、输入文档和终态结构，记录 revised text、格式、图片、表格及修订，不只 finalText。无 Word 驱动时标 not-run，而不是运行空数组后显示成功。

### 3.7 构建、发布与供应链

原 build-info 单测在构建前检查，干净 checkout 无断言通过，本地可能读旧 dist。应普通单测验证 verifier 本身，production build 后必须独立重算并验证本次产物。除了 hash，还要验证必需入口和 worker，不允许缺资产但自洽的空目录通过。

Pages 与 Docker 是两条不同交付路径；静态 Pages 不必等待无关镜像扫描，但必须包含同等源码/产物门禁与生产依赖审计。构建产物尽可能一次生成后分发，记录内容 hash 和源提交；hash 只是归因，不是签名、源码证明或宿主通过证明。

`scripts/docker-server.cjs:143` 原无 `.mjs` MIME，加上 nosniff 后 PDF worker 在浏览器可能拒绝加载。开发/生产 provider route 列表也存在 OpenRouter/SiliconFlow 漂移（`:235`）。应共享能力声明和参数校验，不共享默认开启策略：生产仍显式 opt-in。

供应链门禁分清生产依赖审计、构建依赖风险和镜像扫描，不把 omit=dev 描述为覆盖一切。发布权限限于部署步骤；构建/测试不应持有不需要的跨仓库写 token。部署结果另做资源请求与回滚验证，不把 CI 成功等同终端用户已加载新版本。

### 3.8 安装、性能与能力声明

`sideload-addin.cjs:29-34` 在识别 remove 前要求仓库 manifest，导致源 manifest 缺失时 CLI 卸载也失败。当前两平台安装先修改注册/manifest 再准备启动文档，失败可留下半升级；macOS 卸载按 ProviderName 广泛匹配还需谨慎管理多部署身份。

目标是下载/解析/校验暂存成功后再提交，保存安装身份清单，失败回滚仅限本次改动。不要为了修复安装去自动删除 Word 缓存或注册表大范围项。真实 macOS/Windows 升级与卸载要独立签收；本次不在用户真实 Office 目录执行这些操作。

540 KiB 入口预算是防退化线，不是交互速度证明。same-origin 仍有网络/解析成本，CSS 全量注入与 2,357 行 conversation、3,666 行 word-actions 的复杂度需要按业务能力拆分，而非按行数机械切割。先测 cold start、首个可交互、首 token、分块完成、应用耗时和长会话内存，再按需延迟加载图像/表格等能力。不得为了达预算删掉必要校验或放宽门禁。

## 4. 目标架构与迁移顺序

```text
DOM views / settings draft / accessible dialogs
                    |
RunController (runId, sessionId, cancellation, ownership)
                    |
Capability policy + workflow runners
     |              |                    |
LLM/MCP adapters  Proposal service    Session repository
                    |
Document executor (serialized, approval, preconditions, per-item results)
                    |
Word adapter (anchors, sync, capability checks, tracked-mode scope)

Development harness: authenticated driver protocol + synthetic fixtures
Release evidence: source checks -> built bytes -> served bytes -> real Word acceptance
```

1. **先修确定缺陷并建立回归。** 产物后验收、Pages 门禁、IME、授权撤销、取消观察、存储索引、dev endpoint 边界。改造前记录失败用例，禁止降低覆盖率或简单删除功能。
2. **从最危险入口抽共享契约。** 先接 retry、format、image，再覆盖所有 Word 写入口。每条迁移必须证明原行为和新授权边界，旧代码仅在入口全部迁移后删除。
3. **连接宿主验收与发布。** 少量高价值真 Word 用例先行，不追求立刻复制全部 Jest；输出 build + host + document + result 证据包。人工执行可接受，未经批准的跳过不可接受。
4. **再治理 UI 和能力模块。** settings draft/controller 分离，错误对象标准化，再优化延迟加载和长期存储。React/TypeScript 全面迁移不是前置；若后续组件数量和多人维护成本支持，再以独立决策记录评估。

## 5. 产品完成定义与执行约束

必需验收矩阵见 [产品验收规格](product-acceptance-spec.md)。核心路径至少包括：首次配置、选区/全文提案、部分应用、重复段落漂移、既有修订、表格/图片/图注、取消/重试、附件失败、MCP 副作用、配额清理、更新后的真实构建加载。

接受证据分层：源码与 DOM tests 证明实现分支；产物 verifier 证明本次字节与必需资源；真实 HTTP 证明传输契约；Windows/Mac/Web Word 分别证明宿主行为。模型调用有费用和数据外发，发布会改变外部仓库，真实安装会改用户系统，这些不得仅凭本地自动权限假定已经授权。

不以“本轮已改若干处”宣称整个产品完成。没有真实 Word、真实浏览器布局、provider、容器扫描或安装升级证据时必须单独保留未验收项。已知 P1 未修复时继续列为风险，不以新增文档替代修复。
