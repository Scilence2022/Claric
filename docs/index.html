The workflow工作流程

From instruction to a considered edit.从一句指令，到审慎的修改。

  1. 01

    Ask in context结合文档下指令

    Work on a selection or the whole document. Ask for edits in English or Chinese, without moving your draft out of Word.选中一段或处理全文，用中文或英文提出编辑要求，无需离开 Word 里的草稿。

  2. 02

    Review the proposal审阅修改提案

    Compare before and after, locate the passage, and select the changes to apply. Auto-apply is off by default.对比修改前后，定位原文，选择要应用的改动。自动应用默认关闭。

  3. 03

    Apply, then inspect应用后检查修订

    Text edits use native Word tracked changes. Inspect the result in your document before sharing it with a reviewer.文字编辑使用 Word 原生修订。交给审阅者之前，请在文档中检查实际结果。

Opting into auto-apply gives ongoing permission to apply settled proposals until you turn it off. Structural revisions and formatting fidelity vary by Word host and document.开启自动应用即持续授权应用已生成的提案，直到你将其关闭。结构性修订支持和格式保真度因 Word 宿主及文档而异。 Review the boundaries了解功能边界

Choose how Word connects.选择 Word 的连接方式。

Sideload the hosted add-in for supported cloud services, or self-host for local models and proxy control. You need a compatible Word installation and access to your chosen model.旁加载托管版本以连接支持的云服务，或自托管以使用本地模型和管理代理。你需要兼容的 Word，以及所选模型的访问权限。

Word for macOSmacOS 版 Word

  1. Read the Mac installation guide and inspect the installer source before running it.先阅读 Mac 安装说明并检查安装脚本源码，再决定是否运行。

  3. Open Claric in Word and configure your model endpoint and credentials in Settings.在 Word 中打开 Claric，在设置中配置模型端点和凭据。

Self-host with Docker or npm使用 Docker 或 npm 自托管

  1. Review the repository and choose Docker, or Node.js 22+ for development.检查仓库后选择 Docker，开发环境也可使用 Node.js 22+。
  2. Configure trusted HTTPS certificates, backend endpoints, and the proxy routes your models need.配置受信任的 HTTPS 证书、后端端点及模型需要的代理路由。
  3. Start your server, generate its local manifest, and follow the platform sideloading guide. Keep the server running while using Claric.启动服务，生成本地 manifest，然后按平台指南旁加载。使用 Claric 时需保持服务运行。

Capabilities & boundaries能力与边界

Built for review, with explicit controls.以审阅为核心，控制方式明确。

Text revisions文字修订
Word-level diffs and CJK character-level editing aim to preserve existing formatting. Complex documents still need visual inspection; fidelity is not guaranteed.逐词差异与中日韩文字的字符级编辑力求保留现有格式。复杂文档仍需目视检查，不保证格式完全无损。
Whole-document work全文处理
Heading-aware chunks help process long documents. Summaries, comments, and reusable slash-command skills support repeated editing tasks.按标题分块处理长文档。摘要、批注和可复用的斜杠命令技能支持日常反复进行的编辑任务。
Tables & structure表格与结构
Table creation, cell edits, and formatting proposals extend beyond prose. Native tracking of structural operations depends on Word host APIs; do not assume every operation is a reversible text revision. Keep a backup.除文字外，还可提议创建表格、修改单元格和调整格式。结构操作的原生修订取决于 Word 宿主 API；不要把每个操作都视为可撤回的文字修订。请保留备份。
Persistent auto-apply持续自动应用
Off by default. Enabling auto-apply saves ongoing authorization: settled proposals apply without waiting for another click, including later sessions until disabled. Turn it off to return to manual approval.默认关闭。开启后会保存持续授权：已生成的提案无需再次点击即可应用，并延续到后续会话，直到关闭。关闭后恢复手动确认。
MCP toolsMCP 工具
Connect configured tool servers for additional capabilities. Tools may read or change external systems; inspect server permissions and tool behavior before granting access.连接已配置的工具服务器以扩展能力。工具可能读取或修改外部系统；授权前请检查服务器权限与工具行为。

Independent image settings独立图像设置

Image presets include OpenAI Images, CogView, and MiniMax. Configure image credentials and endpoints separately from chat.图像预设包括 OpenAI Images、CogView 和 MiniMax。图像凭据及端点与聊天模型分开配置。

Static hosting静态托管

Supported cloud presets call provider APIs directly where CORS permits it. There is no same-origin proxy. OpenAI needs a CORS-enabled HTTPS relay; plain HTTP local models are blocked by mixed-content rules.支持的云服务预设在 CORS 允许时直接调用服务商 API，不提供同源代理。OpenAI 需要支持 CORS 的 HTTPS 中继；纯 HTTP 本地模型会被混合内容规则阻止。

Local server本地服务

Docker and npm hosting supply configured same-origin proxy routes for cloud and local backends. That server relays request content and credentials to the selected upstream. Custom endpoints and relays need their own configuration.Docker 和 npm 托管为云端及本地后端提供已配置的同源代理路由。该服务会将请求内容和凭据转发至所选上游。自定义端点及中继需单独配置。

What goes where各类数据发往哪里

  • Chat:聊天： your prompt, supplied document context, and relevant tool results go to the configured chat endpoint, directly or through your proxy.提示词、提供的文档上下文及相关工具结果，直接或经代理发送至配置的聊天端点。
  • Images:图像： generation prompts go to the separately configured image endpoint. A local chat model does not make cloud image generation local.生成提示词发往独立配置的图像端点。本地聊天模型不会让云端图像生成也变成本地处理。
  • MCP: tool arguments go to configured tool servers; returned results may enter chat context. External effects depend on the tools you enable.工具参数发送至配置的工具服务器；返回结果可能进入聊天上下文。外部影响取决于你启用的工具。
  • Stored settings:设置存储： API keys and settings use the add-in origin's localStorage. It is not an encrypted vault. Keys are sent to configured endpoints and may pass through proxies.API 密钥与设置使用加载项来源的 localStorage。它不是加密保险库。密钥会发送至配置的端点，也可能经过代理。

FAQ

Before your first edit.开始编辑之前。

Will Claric edit without asking?Claric 会不经确认直接修改吗？

With the default auto-apply setting off, editing proposals wait for manual approval. Turning it on grants persistent permission to apply settled proposals until you switch it off. MCP tools have their own external effects; the document proposal workflow is not a universal approval gate for external systems.默认关闭自动应用时，编辑提案会等待手动确认。开启后会持续授权应用已生成的提案，直到关闭。MCP 工具有其自身的外部影响；文档提案流程不是所有外部系统操作的统一审批关卡。

Can everything be accepted or rejected as a Word revision?所有操作都能作为 Word 修订接受或拒绝吗？

No. Text edits support native tracked changes, but table structure and other operations depend on the Word host's APIs. Keep a copy of important documents and verify formatting and revision behavior in your version of Word.不能。文字编辑支持原生修订，但表格结构及其他操作取决于 Word 宿主 API。请保留重要文档副本，在你使用的 Word 版本中验证格式与修订行为。

Does choosing a local model keep every request local?选择本地模型后，所有请求都会留在本地吗？

Only if all relevant routes are local. Chat, image generation, and MCP servers are configured separately. Review every endpoint, proxy, and enabled tool before processing sensitive material.只有所有相关路由都在本地时才成立。聊天、图像生成和 MCP 服务器分别配置。处理敏感材料前，请检查每个端点、代理及启用的工具。

Why does a model work in one deployment but not another?为什么同一个模型在不同部署中表现不同？

Static hosting relies on provider CORS and HTTPS support. A local server can proxy requests, but requires reachable backends and trusted certificates. Settings are stored per origin, so switching deployments can require entering credentials again. See the deployment guide for your route.静态托管依赖服务商的 CORS 和 HTTPS 支持。本地服务可以代理请求，但需要可访问的后端及受信任的证书。设置按来源存储，切换部署后可能需要重新输入凭据。请查阅对应部署指南。 Deployment guide ↗部署指南 ↗

What should I try first?第一次适合尝试什么？

Use a copy of a short document. Configure your model, leave auto-apply off, and ask for a small edit to a selection. Review the proposal and inspect the resulting Word revisions before trying whole-document or structural edits.使用一份短文档的副本。配置模型，保持自动应用关闭，针对选中文本请求一处小修改。审阅提案并检查 Word 中的修订结果，再尝试全文或结构性编辑。
